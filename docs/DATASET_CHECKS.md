## MURA access conditions, read from the Stanford AIMI / Redivis "Access" panel (Nov 2026, user logged in; nothing was submitted or agreed)
* Overview and metadata access: **public**. **Data access** (table cells and files) needs 2 requirements: (1) **AIMI membership** (complete for the logged-in user); (2) **"Stanford_Research_Agreement" per dataset: "Not approved for this dataset" -> button "Apply"**.
* The text of the Stanford_Research_Agreement is shown only inside the application step (behind "Apply"); I did not start the application. **Read it yourself before submitting the paper** (look for: non-commercial/research-only use, no redistribution, citation, publication or security clauses).
* Usage rules: **Data exports: Unrestricted** (users with access may export tables derived from the dataset).
* Consequence for the paper: MURA is "available to registered researchers after approval of a dataset research agreement (Stanford AIMI)", not freely downloadable. The Kaggle mirror (`cjinny/mura-v11`, licence "Unknown") does not replace that agreement: say this explicitly and, if possible, apply for the official access (use the BAUET affiliation) and note the date.

## MURA mirror vs official index -- hash check done (7 Nov 2026)
Kaggle notebook (CPU, Accelerator None, 518 s) compared every PNG of `cjinny/mura-v11` with the official Stanford AIMI Redivis `MURA-v1.1` file index (40,009 PNG entries): **40,005 of 40,005 mirror images are identical in path, size and MD5 (first 48 bits)** (train 36,808, valid 3,197); 0 differences, 0 images only in the mirror; the 4 entries only in the official index are `._image*.png` macOS metadata files. Conclusion: the mirror holds the same images as the official release. The check notebook embeds official file names and hashes, so it is NOT published in the repository.
